# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This repository is a personal Emacs configuration consisting of a single file, `init.el`. There is no build system, package manifest, or test suite — `init.el` is both the source and the artifact.

## Validating changes

There's no CI or test runner. To check that edits are well-formed and load cleanly:

```sh
emacs --batch -l init.el --eval '(message "init.el loaded OK")'
```

This starts a fresh, headless Emacs, loads the config (installing any missing `use-package` packages via `package-archives`), and exits. Expect it to be slow the first time a new package is introduced, since `use-package-always-ensure` triggers a real download/install.

To sanity-check elisp syntax alone (parens balance, no byte-compile warnings) without pulling packages:

```sh
emacs --batch --eval '(check-parens)' -l init.el
```

## Structure of init.el

The file is organized into banner-commented sections, in load order:

1. **UI chrome** (top of file) — menu/tool bar, fringes, line numbers, font. These `setq`/mode calls run before `package.el` is initialized, so they must not depend on any package.
2. **Package bootstrap** — `package.el` init with MELPA plus GNU/NonGNU ELPA, and `package-archive-priorities` set so tagged GNU/NonGNU releases win over MELPA's rolling date-based snapshots (MELPA versions like `20260721.2157` numerically sort above semantic versions like `4.6.0`, so without explicit priorities MELPA is always preferred even when a more stable release exists elsewhere). `use-package-always-ensure` is set so every `use-package` block below auto-installs.
3. **Behaviour** — editing defaults (`indent-tabs-mode`, backups/autosave disabled, etc.) and global minor modes (`global-auto-revert-mode`, `savehist-mode`, `electric-pair-mode`, etc.), all built-ins, no `use-package`.
4. **Feature blocks**, each its own `use-package` form: theme (`doom-themes`), modeline (`doom-modeline`), minibuffer completion stack (`vertico` + `orderless` + `marginalia` + `consult`), in-buffer completion (`corfu`), `which-key`, `magit`, `multiple-cursors`, `project.el` (built-in, just a keybinding), `treesit-auto`, `eglot` (LSP, hooked to `-ts-mode` variants for python/js/typescript/rust), and per-language modes (`markdown-mode`, `yaml-mode`, `rust-mode`, `csv-mode`, `nix-mode`).
5. **Clojure stack** — a deliberately grouped set of interdependent packages: `paredit` (structural editing) → `rainbow-delimiters` → `clojure-mode` → `cider` (`:after clojure-mode`) → `clj-refactor` (`:after (clojure-mode cider)`). Keep this ordering when editing, since later blocks rely on `:after` to load correctly.
6. **`exec-path-from-shell`** — imports shell env vars (notably Nix-related: `NIX_SSL_CERT_FILE`, `NIX_PROFILES`, `__ETC_PROFILE_NIX_SOURCED`, `XDG_DATA_DIRS`) into Emacs's process environment, since GUI Emacs doesn't otherwise see a login shell's env. Relevant if Emacs is run on a Nix-managed system.
7. **Keybindings** (bottom) — global keys layered on top of package-specific `:bind` clauses declared in their own `use-package` blocks above.
8. **Custom-set variables/faces block** — auto-managed by Emacs's Customize UI (`package-selected-packages`, `safe-local-variable-values`, `custom-safe-themes`). Don't hand-edit the package list here; it's regenerated by Emacs. `safe-local-variable-values` whitelists CIDER-related directory-local variables used by specific Clojure projects (e.g. `cider-clojure-cli-aliases`).

## Conventions to preserve when editing

- New packages go through `use-package`, with `:hook`/`:bind`/`:custom` keywords rather than bare `add-hook`/`setq` after `:config`, matching the existing style.
- Section banners (`;;; ─── NAME ───...`) mark top-level feature groups — add new packages to an existing section or create a new banner rather than interleaving unrelated config.
- Comments explain *why* a non-obvious setting exists (e.g. the MELPA-versioning note, the CIDER quick-reference, the paredit/cider `:after` ordering) — keep that pattern rather than commenting on what a form obviously does.
